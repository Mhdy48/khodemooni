# خیاط خودمونی

محتوای سایت را فارسی بنویسید. در `index.html` می‌توانید متن، عنوان، توضیح تصویر و برچسب فرم را مستقیم به فارسی وارد کنید. متن‌های مشترک و پیام‌های تعاملی در `src/locales/fa.js` قرار می‌گیرند. برای نمایش یک پیام مشترک در قالب از `{{key}}` استفاده کنید. برای ثابت نگه داشتن یک نام در هر دو زبان، روی عنصر آن `translate="no"` بگذارید.

وقتی `npm run dev` باز است، با ذخیرهٔ متن فارسی، ترجمهٔ عبارت‌های تازه یا تغییرکرده در پس‌زمینه آماده می‌شود. برای آماده‌سازی دستی یا تلاش دوباره پس از قطع اینترنت یا پایان سهمیه، `npm run translate` را اجرا کنید. این کار فقط متن سایت را به MyMemory می‌فرستد.

پیش‌نویس‌ها در `translations/ar-memory.json` ذخیره می‌شوند. هر ردیف متن فارسی و ترجمهٔ عربی را کنار هم دارد. ردیف‌های تازه برچسب سوم `"draft"` دارند. برای بازبینی، ترجمه را ویرایش کنید و این برچسب را بردارید. ترجمهٔ بازبینی‌شده تا وقتی متن فارسی عوض نشود حفظ می‌شود. فایل ترجمه را همراه محتوای فارسی در Git ثبت کنید.

ساخت و انتشار هر دو مسیر کاملاً از فایل‌های محلی انجام می‌شود. پیش‌نویس ذخیره‌شده قابل نمایش است. اگر ترجمه‌ای در انتظار آماده‌سازی باشد، ساخت نام کلید آن را گزارش می‌کند. در مسیر عربی، برای کلید موجود آخرین ترجمهٔ ذخیره‌شده و برای کلید کاملاً تازه متن فارسی نمایش داده می‌شود.

## اجرای محلی

پروژه با Node.js 26 و npm 11 آزمایش شده است. در پوشهٔ پروژه اجرا کنید.

```sh
npm ci
npm run dev
```

فارسی در مسیر `/` و عربی در `/ar/` باز می‌شود. با انتخاب زبان دیگر، مرورگر صفحهٔ مقصد را در همان بخش باز می‌کند و لودینگ سایت طبق تنظیمات حرکت کاربر اجرا می‌شود. `npm run build` هر دو صفحه را در `dist` می‌سازد و `npm run preview` خروجی را محلی نمایش می‌دهد. هنگام انتشار، `SITE_ORIGIN` را مطابق `.env.example` تنظیم کنید تا لینک‌های canonical و hreflang با دامنهٔ عمومی ساخته شوند.

## توسعه و بررسی

- ورودی استایل هر دو صفحه `src/styles/tailwind.css` است. رنگ‌ها و فونت‌های تم در `src/styles/theme.css`، استایل‌های عمومی در `src/styles/base.css` و انیمیشن‌های مشترک در `src/styles/animations.css` قرار دارند. استایل اختصاصی هر بخش را در `src/styles/sections` پیدا می‌کنید.
- تعاملات از `src/main.js` راه‌اندازی می‌شوند. رفتار هر بخش در `src/modules` و پیام‌های اعتبارسنجی فرم در `src/locales` قرار دارد.
- با `npm run check` تحلیل کد، قالب‌بندی، تست‌های ساختار، build و تست تعاملی فرم و گالری اجرا می‌شوند. تست مرورگر از Chrome نصب‌شده استفاده می‌کند. برای انتخاب مرورگر دیگری از خانوادهٔ Chromium، مسیر فایل اجرایی را در `CHROME_PATH` قرار دهید.
- برای اجرای آزمون‌های تصویری مانند `node scripts/hero-check.mjs`، سرور توسعه را باز نگه دارید. نشانی پیش‌فرض تست‌ها `http://localhost:5173/` است و با `TEST_URL` تغییر می‌کند.

## دریافت درخواست مشاوره

در اجرای محلی با نشانی 127.0.0.1 یا localhost، فرم در هر دو زبان درخواست را در پایگاه SQLite خصوصی کاربر، خارج از پوشهٔ سایت، ذخیره می‌کند. با `npm run consult:list` صد درخواست آخر روی همان دستگاه دیده می‌شود. مسیر پیش‌فرض `~/.khodemooni/consultations.sqlite` است و با `CONSULT_DB` قابل تغییر است. نمایش موفقیت به تأیید شناسهٔ درخواست وابسته است.

GitHub Pages فقط فایل ایستا منتشر می‌کند. تا زمان اتصال گیرنده، پنجرهٔ مشاوره شمارهٔ کارگاه و وضعیت ثبت آنلاین را نشان می‌دهد. برای راه‌اندازی گیرنده روی میزبان Node 26 با دیسک ماندگار، `npm run consult:serve` را زیر یک مدیر فرایند اجرا کنید. گیرنده روی 127.0.0.1 و پورت 4174 (یا PORT) گوش می‌دهد. مسیر /api/consultations را از طریق پراکسی HTTPS در دسترس قرار دهید. CONSULT_SITE_ORIGIN باید مبدأ دقیق سایت عمومی باشد و متغیر مخزن VITE_CONSULT_ENDPOINT باید نشانی کامل HTTPS این مسیر باشد. پس از تنظیم، سایت را مجدداً بسازید. محدودیت پذیرش هشت درخواست تازه در ده دقیقه به ازای نشانی اتصال است؛ در استقرار پشت پراکسی، محدودیت مشتری را در پراکسی نیز تنظیم و سهمیهٔ گیرنده را با حجم واقعی هماهنگ کنید. این نسخه اعلان خودکار برای کارگاه ارسال نمی‌کند.
